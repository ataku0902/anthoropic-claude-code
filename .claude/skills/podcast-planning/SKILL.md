# ポッドキャスト企画・コンセプト設計

## 使用開始時の宣言

作業に入る前に、必ず一言宣言する。例：「ポッドキャスト企画スキルを使います。まず属性の棚卸しからいきます。」
黙って Phase 0 の質問を始めない。ユーザーが、自分の意図どおりにスキルが起動したかを確認できるようにするため。
宣言は1文で足りる。スキルの構成説明は不要。

## このスキルのゴール

ゴールは企画書を作ることではなく、**半年後もその番組の配信が続いている状態**を作ること。

ポッドキャストは1本では価値が出ない。20本、50本と積み上がったときに初めて検索から人が流れ込み、資産になる。
逆に言えば、5本で止まる企画は「面白いかどうか」以前に失敗している。

したがって企画書の評価軸は「面白そうか」ではなく、**「この人は20本先まで話すことがあるか」**とする。
この基準は Phase 1 と Phase 6 の2か所で機械的に検査する。ここを甘くすると、企画書だけが立派で配信が続かないものができあがる。

---

## 音声メディアの力学（企画の前提）

企画の判断は、常にこの4つの制約の上で行う。

| 前提 | 企画への影響 |
|---|---|
| **発見されにくい** | 動画や記事と違い、偶然の流入はほぼない。だから「誰に向けた番組か」をタイトルと1話冒頭で自分から名乗る必要がある |
| **完聴率・リピート率が異常に高い** | 一度掴んだリスナーは長く深く聴く。広く浅く狙うより、狭く深く刺す設計が勝つ |
| **「ながら聴き」が主戦場** | 通勤・家事・入浴中に聴かれる。手も目も塞がっている前提なので、図表や複雑な構造に頼れない。話し言葉だけで完結させる |
| **ストックが資産になる** | 半年前の1本目が今日も再生される。継続できない企画は、どれだけ良くても資産にならない |

日本のポッドキャスト利用率は米国の10年前の水準にあり、先行者利益が取れる局面にある。
ただしこれは「早く始めれば勝てる」という意味ではなく、**「続けた人だけが先行者になる」**という意味として扱う。

## Phase 0: 属性の棚卸し

「誰が語るか」は音声メディアにおける最大の差別化要因である。同じ話でも、語り手の属性が変われば別の番組になる。
だからテーマより先に、話し手そのものを言語化する。

以下を埋める。不足があれば**推測で埋めず、ユーザーに聞く**。一度に全部聞かず、埋まっていない項目だけをまとめて聞く。

| 項目 | なぜ必要か |
|---|---|
| 年齢・世代 | 同世代のリスナーが「自分ごと」として聴く入口になる |
| 住んでいる場所 | 「地方」ではなく市町村名まで。固有名詞は代替不能な強みになる |
| 職業・職歴・所属 | 外からは見えない業界の内部構造を持っている可能性が高い |
| 今のライフステージ | 例：独身・共働き・子育て中・転職活動中・介護中。ここが共感の発火点になる |
| 続けている趣味・偏愛の対象 | 熱量が自然に出る領域。継続の燃料になる |
| 語れる失敗・決断 | ライフヒストリー型の核。誰にも真似できない一次情報 |
| 収録に使える時間と頻度 | 週1で15分か、月2で40分か。ここで台本の設計が変わる |
| すでに持っている素材 | 過去の原稿、写真、日記、仕事で作った資料など |
| 顔出し・実名の方針 | Phase 8 の制約チェックに直結する |

ユーザーが「テーマはもう決まっている」と言ってきても、**Phase 0 は飛ばさない**。
属性が言語化されていないテーマは、たいてい他の誰でも言える話になっていて、Phase 2 で組み直すことになる。

## Phase 1: テーマの耐久テスト（最重要）

ここがこのスキルの心臓部にあたる。飛ばすと企画全体が無駄になる。

ユーザーは多くの場合、**「今いちばん頭を占めていること」**を持ってくる。転職活動、ダイエット、資格試験、進行中のプロジェクト。
熱量が高いので一見良いテーマに見えるが、この種のテーマは**結論が出た瞬間に終わる**。20本持たない。

### ストック型とフロー型

| 種類 | 中身 | 寿命 |
|---|---|---|
| **ストック型** | 普遍的なノウハウ、人生観、土地や職業の構造、価値観 | いつ聴いても価値が変わらない |
| **フロー型** | 時事、トレンド、進行中の個人的イベント | 今聴くことに意味があるが、風化が早い |

番組の**軸はストック型で立て、フロー型は燃料として後から混ぜる**。逆にすると番組ごと終わる。

### 耐久テスト3問

ユーザーが持ってきたテーマに、この3問を当てる。

1. **このテーマは1年後も自分の中に残っているか？** 結論が出たら消えるものはフロー型。
2. **熱が冷めた日でも、義務として20本話せるか？** 熱量頼みの企画は12本目あたりで止まる。
3. **「そのテーマの人」と呼ばれて嫌ではないか？** 番組が育つほど、その看板は外せなくなる。

### フロー型だったときの扱い

捨てない。**そのテーマの一段下にある土台を探す。** 熱があるということは、その下に必ず価値観がある。

| 持ってきたテーマ（フロー） | 一段下の土台（ストック） |
|---|---|
| 転職活動 | なぜこの土地・この職を選んだのか／働き方の選択 |
| ダイエット | 30代の体との付き合い方 |
| 資格試験の勉強 | 働きながら学び直すということ |
| 子どもの受験 | 親として何を手放すか |

土台をテーマにし、もとの熱いネタは「フロー回」として Phase 6 のリストの外に置く。配信21本目以降の弾になる。

**ユーザーが持ってきたテーマをそのまま通さない。** 通してしまうと、このスキルは単なる清書係になる。

## Phase 2: ポジショニング確定

公式は **【属性】×【テーマ】**。属性を具体化するほど、リスナーは「これは自分のための番組だ」と感じる。

| 良し悪し | 例 | 理由 |
|---|---|---|
| 弱い | 「会社員」×「仕事術」 | 誰でも言える。代替可能 |
| 強い | 「人口3万人の町の26歳公務員」×「地元で働くという選択」 | 属性が固有名詞まで降りていて代替不能 |
| 弱い | 「主婦」×「料理」 | 番組が無数にある |
| 強い | 「育児中の母親」×「偏食の子ども向けレシピ」 | 困っている人が specific に想像できる |

確定したら、その組み合わせで既存番組を調べる。同じ番組がすでにあるなら、**属性をもう一段具体化する**（地域・年齢・立場・状況のどれかを足す）。
テーマ側を変えるより属性側を絞るほうが、たいてい早く独自性に届く。

---

## Phase 3: ターゲットを1人に絞る

「20〜40代の社会人」のような幅で書かない。幅で書いた瞬間、誰にも刺さらない番組になる。
1人に深く刺されば、同じ状況にいる1万人に届く。狭く書くことは、届く範囲を狭めることではない。

この型で書く：

> ○歳、○○に住んでいて、○○をしている。最近○○で悩んでいる。○○の○分間に何かを聴いている。

「最近○○で悩んでいる」が最も重要。**その悩みが、番組を聴き始める理由そのものになる。**

---

## Phase 4: 提供価値と出演形態

### 4大価値から主軸1つ・副軸1つを選ぶ

「おもしろい」は分解すると次の4つになる。全部狙うと薄まるので、主軸を1つだけ決める。

| 価値 | 中身 | 向いているテーマ |
|---|---|---|
| **発見** | 未知の事柄を知る喜び | 業界の内側、専門知識、知られていない土地 |
| **理解** | 複雑な事象が噛み砕かれ、腑に落ちる快感 | 制度、仕組み、専門分野の解説 |
| **共感** | 「自分と同じだ」という安心感 | ライフステージの悩み、決断、失敗談 |
| **空間** | その場に同席しているような没入感 | 雑談、複数人の掛け合い |

### 出演形態

| 形態 | 長所 | 短所 |
|---|---|---|
| ひとり語り | 調整がゼロ。いつでも録れる | テンポを自力で作る技術が要る |
| 固定された複数人 | 掛け合いで「良い空間」が生まれやすい | 相手の都合に配信が縛られる |
| ゲストトーク | 話題が外から供給される | ホストの準備負担が大きい |

複数人の場合、**声だけで聞き分けられる上限は3人まで**。3人なら「先生（専門家）×生徒（初心者・質問役）」の役割分担を入れると、情報の解像度が上がる。

### ひとり語りを選んだ場合は、必ず対策を設計に入れる

ひとり語りは相手がいないので「間」が死にやすい。次のどちらかを企画書に明記する。

- **3分×3ブロック構成**：メイントークを3分ずつに割り、各ブロックの頭に問いを立てる。質問役を自分で用意する形。
- **想定リスナーへの呼びかけ**：Phase 3 で決めた1人に話しかける形式にし、「〜ですよね」「〜って思いませんか」で相手の存在を作る。

音質・声質・テンポ・音量バランス・関係性の5つが「良い空間」を作る要素だが、ひとり語りでは「関係性」が使えない。その分をテンポで補う設計になる。

## Phase 5: タイトル3案

命名の公式は **「誰が」「何を語り」「どんなベネフィットがあるか」を1秒で伝える**こと。

必ず**3案出し、それぞれ何を優先したかを明記する**。1案だけ出すと、ユーザーは比較できず判断を委ねられない。

3案は狙いを変えて作る：

| 型 | 狙い | 例 |
|---|---|---|
| 属性明示型 | 検索性と「自分ごと」化 | 『人口3万人の働き方 ―26歳、地方公務員―』 |
| 覚えやすさ型 | 口コミで伝わる短さ | 『役所の窓から』 |
| 共感狙い撃ち型 | ターゲットの悩みを直接言う | 『辞めるか、残るか、その前に』 |

参考になる実在の型：
- 『News Connect ―あなたと経済をつなぐ5分間―』… 所要時間で価値を提示
- 『経営中毒 ―だれにも言えない社長の孤独―』… ターゲットと共感ポイントを狙い撃ち
- 『超実践的幸福論』… 抽象を具体化し、期待値を設定

3案のうち1つを推奨し、理由を1行で書く。副題は本題を説明する役割なので、本題だけで属性が伝わらないときに足す。

## Phase 6: ストック型20本のテーマリスト

**ここが企画の合否判定になる。** 20本書けなければ Phase 1 に戻る。書けたこと自体が、コンセプトが揺るがない証明になる。

4つのカテゴリに分散させる。1つに偏ると番組が痩せる。

| カテゴリ | 狙う価値 | 中身 |
|---|---|---|
| A. 開示 | 発見 | 外からは見えない仕事・立場の内側 |
| B. 選択と価値観 | 共感 | なぜそれを選んだか、何を捨てたか |
| C. 偏愛の対象 | 好きなもの | 熱量を持って推せる対象。継続の燃料 |
| D. 普遍ノウハウ | 理解 | 誰かの役に立つ、時間が経っても古びない知見 |

各テーマは**1本分の話として成立する粒度**まで具体化する。「仕事について」は不可。「窓口の裏側で実際に何が起きているか」なら可。

**第1回に置くのは「一番刺さるもの」ではなく「一番自分が話しやすいもの」**にする。
1本目は必ず不慣れで、ここで力尽きる人が多い。最強のネタは3〜5本目、話し方に慣れた頃に置く。

---

## Phase 7: 台本フォーマットの雛形

プロの「自由なトーク」は綿密な設計の上に成り立っている。ただし**一言一句は書かない**。書くと読み上げになり、ライブ感が死ぬ。

5パーツ構成に、経過時間の目安（タイムコード）を入れる。収録中の進行管理が劇的に楽になる。

| パーツ | 役割 |
|---|---|
| オープニング | 番組の趣旨説明。毎回同じ定型文で「定着」を狙う |
| アイスブレイク | 場の空気を温める。2〜3分 |
| メイントーク | 内容の核 |
| 振り返りトーク | 気づきや学びの要約 |
| エンディング | 告知とSNS誘導 |

尺は「ながら聴き」の1区間（通勤・家事）に収まる**15〜20分**を初期値とし、ユーザーの条件に合わせて調整する。

メイントークの設計に2つ入れる：

- **PREP法**：結論(P)→理由(R)→具体例(E)→結論(P)。論理的な心地よさが生まれる。
- **ファクトを最低3つ**：主観的な「意見」だけでは薄い。数字・固有名詞・実際の出来事を混ぜると密度が出る。

## Phase 8: 職業上の制約チェック

**必ず実施する。** 配信を始めてから気づくと、公開済みの回を全部消す作業になる。企画段階なら設計で回避できる。

ユーザーが公務員の場合、最低この3点を確認し、企画書に明記する。

| 論点 | 確認すること |
|---|---|
| 副業・営利従事 | 収益化（広告・投げ銭・スポンサー）すると許可申請が必要になる可能性が高い。当面は非収益で設計するのが安全 |
| 守秘義務 | 個別案件、個人情報、未公表の政策・数値は出さない。「制度の一般論」か「自分の私的体験」に収まるようテーマを設計する |
| 信用失墜行為 | 職場・上司・住民への批判は避ける。主語を常に「自分」にすると自然に回避できる |

会社員・専門職の場合も同様に、就業規則の副業規定・守秘義務・所属明示の可否を確認する。
加えて、顔出し／実名／勤務先の特定可能性をどこまで許容するかを決め、企画書に書いておく。

Phase 6 の20本リストを、この観点で1本ずつ点検する。引っかかるものは削るのではなく、**抽象度を1段上げて残せないか**を先に検討する。

---

## 出力

`references/output_template.md` をそのまま型として使い、Markdownファイルを作成する。
Obsidianのvaultに置く前提なので、テンプレートのYAMLフロントマターとチェックボックスはそのまま残す。

ファイル名は `ポッドキャスト企画_<番組名>.md` とする。
出力先をユーザーが指定していなければ、作成後にパスを伝えて「Obsidianのvaultに移してください」と案内する。

---

## やってはいけないこと

- **ユーザーが持ってきたテーマをそのまま通す**（Phase 1 の耐久テストを省略する）。このスキルの価値の大半がここにある
- ターゲットを「20〜40代」のような幅で書く
- 20本に満たないまま企画書を出す。書けなかったこと自体が重要な発見なので、ごまかさずユーザーに伝えて Phase 1 に戻る
- タイトルを1案だけ出す
- 「面白い番組にしましょう」で終わらせる。面白さは必ず4大価値のどれかに翻訳する
- 属性を聞かずにテーマから入る。誰が語るかが決まっていない企画は、他の誰でも作れる
